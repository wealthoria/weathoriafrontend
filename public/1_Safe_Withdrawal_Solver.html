1. ಈ calculator ಏನು ಮಾಡುತ್ತದೆ

Safe Withdrawal Solver ಒಂದೇ ಪ್ರಶ್ನೆಗೆ ಉತ್ತರ ಕೊಡುತ್ತದೆ:

₹ ? / month ನನ್ನ ಹತ್ತಿರ ಇರುವ corpus ಇಂದ, ನನ್ನ retirement horizon ಪೂರ್ತಿ ಮುಗಿಯುವವರೆಗೆ,
ನಾನು ಬಯಸಿದ success probability ಉಳಿಸಿಕೊಂಡು — ತಿಂಗಳಿಗೆ ಎಷ್ಟು ತೆಗೆಯಬಹುದು?

ಇಲ್ಲಿ ಗಮನಿಸಬೇಕಾದ ವಿಷಯ — ಇದು reverse calculator. ಸಾಮಾನ್ಯ SIP calculator ನಲ್ಲಿ ನೀವು amount ಕೊಟ್ಟು "ಎಷ್ಟು ಆಗುತ್ತದೆ" ಎಂದು ಕೇಳುತ್ತೀರಿ. ಇಲ್ಲಿ ನೀವು ಬೇಕಾದ safety level ಕೊಡುತ್ತೀರಿ, ಮತ್ತು calculator ಆ safety level ಗೆ ಸರಿಹೊಂದುವ withdrawal amount ಅನ್ನು ಹುಡುಕಿ ಕೊಡುತ್ತದೆ.

ಇದನ್ನು ಸಾಧಿಸಲು ಅದು ನಿಮ್ಮ retirement ಅನ್ನು ಸಾವಿರಾರು ಬಾರಿ simulate ಮಾಡುತ್ತದೆ (Monte Carlo), ಪ್ರತಿ ಬಾರಿಯೂ ಬೇರೆ ಬೇರೆ market returns ಬಳಸಿ. ಆಮೇಲೆ "ಎಷ್ಟು simulations ನಲ್ಲಿ ಹಣ ಉಳಿಯಿತು?" ಎಂದು ಎಣಿಸುತ್ತದೆ.

2. ಯಾವ ಸಮಸ್ಯೆಯನ್ನು ಇದು ಬಗೆಹರಿಸುತ್ತದೆ

2.1 "4% rule" ನ ಸಮಸ್ಯೆ

ಬಹಳ ಜನ ಕೇಳಿರುತ್ತಾರೆ — "corpus ನ 4% ವರ್ಷಕ್ಕೆ ತೆಗೆದರೆ safe". ಈ rule 1994 ರಲ್ಲಿ William Bengen ಎಂಬವರು US market data (1926–1976) ಮೇಲೆ ಮಾಡಿದ study ಇಂದ ಬಂದದ್ದು. ಆದರೆ ಅದನ್ನು ಭಾರತೀಯ ಸಂದರ್ಭಕ್ಕೆ ನೇರವಾಗಿ ತರುವುದು ಅಪಾಯಕಾರಿ:

4% rule ನ ಊಹೆಭಾರತದಲ್ಲಿ ವಾಸ್ತವ
30-year horizonಭಾರತದಲ್ಲಿ ಜನ 50–55 ಕ್ಕೆ retire ಆದರೆ horizon 35–40 ವರ್ಷ ಆಗಬಹುದು. Horizon ಉದ್ದ ಆದಷ್ಟು safe rate ಕಡಿಮೆ ಆಗುತ್ತದೆ.
Inflation ~3%ಭಾರತದಲ್ಲಿ CPI 5–6%, ಆದರೆ ನಿಮ್ಮ personal inflation (medical, education, help) 7–9% ಇರಬಹುದು.
US equity + bond mixಭಾರತೀಯ equity volatility ಹೆಚ್ಚು (SD 18–22%), ಆದರೆ expected return ಕೂಡ ಹೆಚ್ಚು.
Fee drag ಇಲ್ಲRegular plan MF ನಲ್ಲಿ TER 1.5–2.2%. ಇದು 30 ವರ್ಷದಲ್ಲಿ ದೊಡ್ಡ ಮೊತ್ತ ತಿನ್ನುತ್ತದೆ.
100% success ಬೇಕು100% ಬೇಕು ಅಂದರೆ ನೀವು ತುಂಬಾ ಕಡಿಮೆ ಖರ್ಚು ಮಾಡಿ, ದೊಡ್ಡ ಮೊತ್ತ ಬಿಟ್ಟು ಸಾಯುತ್ತೀರಿ. ಅದೂ ಒಂದು ನಷ್ಟವೇ.

ಈ calculator ಆ ಎಲ್ಲಾ parameters ಅನ್ನು ನೀವೇ set ಮಾಡುವಂತೆ ಮಾಡುತ್ತದೆ. ಒಂದು universal rule ಬದಲು — ನಿಮ್ಮ ಸ್ವಂತ ಸಂಖ್ಯೆ.

2.2 Sequence risk ಎಂಬ ದೊಡ್ಡ ಅಪಾಯ

ನೀವು ವರ್ಷಕ್ಕೆ average 11% return ಪಡೆಯುತ್ತೀರಿ ಅಂದುಕೊಳ್ಳಿ. ಆದರೆ retirement ನ ಮೊದಲ 3 ವರ್ಷ market −30%, −10%, −5% ಆದರೆ? ನೀವು ಆ ಬಿದ್ದ portfolio ಇಂದಲೇ ಪ್ರತಿ ತಿಂಗಳು ಹಣ ತೆಗೆಯುತ್ತಿರುತ್ತೀರಿ — ಅಂದರೆ ಕಡಿಮೆ ಬೆಲೆಗೆ units ಮಾರುತ್ತಿರುತ್ತೀರಿ. Market ಮತ್ತೆ ಮೇಲೆ ಬಂದಾಗ ನಿಮ್ಮ ಹತ್ತಿರ ಆ ಏರಿಕೆ ಅನುಭವಿಸಲು ಸಾಕಷ್ಟು units ಉಳಿದಿರುವುದಿಲ್ಲ.

ಇದನ್ನೇ sequence-of-returns risk ಅನ್ನುತ್ತಾರೆ. Average ಒಂದೇ ಆದರೂ, returns ಬರುವ ಕ್ರಮ ನಿಮ್ಮ ಫಲಿತಾಂಶವನ್ನು ಸಂಪೂರ್ಣ ಬದಲಾಯಿಸುತ್ತದೆ. ಒಂದೇ average return ನಲ್ಲಿ ಕೆಲಸ ಮಾಡುವ ಸಾಮಾನ್ಯ Excel sheet ಈ ಅಪಾಯವನ್ನು ಸಂಪೂರ್ಣ ಮರೆಮಾಚುತ್ತದೆ.

ಮುಖ್ಯ ಅಂಶ

Accumulation phase ನಲ್ಲಿ (ನೀವು ಹೂಡಿಕೆ ಮಾಡುತ್ತಿರುವಾಗ) ಮೊದಲಿನ crash ನಿಜವಾಗಿ ಒಳ್ಳೆಯದು — ಕಡಿಮೆ ಬೆಲೆಗೆ units ಸಿಗುತ್ತವೆ. Withdrawal phase ನಲ್ಲಿ ಅದೇ crash ಮಾರಕ. ಇದೇ ಕಾರಣಕ್ಕೆ retirement planning ಗೆ ಬೇರೆ tool ಬೇಕು.

3. Core concept — Success Probability

ಈ calculator ನ ಪ್ರತಿಯೊಂದೂ "success probability" ಎಂಬ ಒಂದೇ ಸಂಖ್ಯೆಯ ಸುತ್ತ ತಿರುಗುತ್ತದೆ. ಅದರ ವ್ಯಾಖ್ಯೆ ಸರಳ:

# ಒಂದು simulation "success" ಆಗುತ್ತದೆ, ಒಂದು ವೇಳೆ — horizon ಮುಗಿಯುವಷ್ಟರಲ್ಲಿ portfolio value >= bequest target # Success probability = (success ಆದ paths ಸಂಖ್ಯೆ) / (ಒಟ್ಟು paths ಸಂಖ್ಯೆ) x 100

ಉದಾಹರಣೆಗೆ 1,200 simulations ನಲ್ಲಿ 1,080 ರಲ್ಲಿ ಹಣ ಉಳಿಯಿತು ಅಂದರೆ success probability = 1080/1200 = 90%.

3.1 90% ಅಂದರೆ ಏನು — ಮತ್ತು ಏನಲ್ಲ

ಏನು ಅರ್ಥ: ಈ calculator ಬಳಸಿದ return distribution ಮತ್ತು assumptions ಸರಿ ಇದ್ದರೆ, 10 ಸಾಧ್ಯ ಭವಿಷ್ಯಗಳಲ್ಲಿ 9 ರಲ್ಲಿ ನಿಮ್ಮ ಹಣ ಮುಗಿಯುವುದಿಲ್ಲ.

ಏನು ಅರ್ಥವಲ್ಲ: ಇದು ನಿಜ ಜಗತ್ತಿನ probability ಅಲ್ಲ. ಇದು ಈ model ನ ಒಳಗಿನ probability. Model ನ assumptions (return, SD, inflation) ತಪ್ಪಿದರೆ ಈ ಸಂಖ್ಯೆಯೂ ತಪ್ಪು. ಆದ್ದರಿಂದ ಇದನ್ನು ಗ್ಯಾರಂಟಿ ಅಲ್ಲ, ಒಂದು stress test ಎಂದು ನೋಡಿ.

ಎಚ್ಚರಿಕೆ

10% failure ಅಂದರೆ "10% ಸಂದರ್ಭದಲ್ಲಿ ನಾನು ಬೀದಿಗೆ ಬರುತ್ತೇನೆ" ಎಂದಲ್ಲ. ವಾಸ್ತವದಲ್ಲಿ portfolio ಕಡಿಮೆ ಆಗುತ್ತಿರುವುದನ್ನು ನೋಡಿ ನೀವು ಖರ್ಚು ಕಡಿಮೆ ಮಾಡುತ್ತೀರಿ. ಈ model ಆ adjustment ಮಾಡುವುದಿಲ್ಲ — ಅದು ಕುರುಡಾಗಿ ಪ್ರತಿ ತಿಂಗಳು ಅದೇ ಮೊತ್ತ ತೆಗೆಯುತ್ತಲೇ ಇರುತ್ತದೆ. ಆದ್ದರಿಂದ ನಿಜ ಜೀವನದ failure ಇದಕ್ಕಿಂತ ಕಡಿಮೆ.

5. ಒಳಗಿನ Math — engine ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ

5.1 ಹಂತ 1 — Lognormal calibration

Returns ಅನ್ನು normal distribution ಇಂದ ನೇರವಾಗಿ ತೆಗೆದರೆ ಒಂದು ಸಮಸ್ಯೆ ಬರುತ್ತದೆ: −150% return ಬರಬಹುದು, ಅಂದರೆ portfolio ನೆಗೆಟಿವ್ ಆಗುತ್ತದೆ. ಅದು ಅಸಾಧ್ಯ. ಆದ್ದರಿಂದ ಈ calculator lognormal distribution ಬಳಸುತ್ತದೆ — ಅಲ್ಲಿ growth factor ಯಾವಾಗಲೂ ಧನಾತ್ಮಕ.

ಆದರೆ ನೀವು ಕೊಡುವುದು arithmetic mean (11%) ಮತ್ತು SD (16%). ಅವನ್ನು lognormal ನ parameters (μ, σ) ಗೆ ಪರಿವರ್ತಿಸಬೇಕು:

// meanPct = 11, sdPct = 16 mu = 0.11 // arithmetic mean, decimal ನಲ್ಲಿ sd = 0.16 sig2 = ln( 1 + sd² / (1+mu)² ) = ln( 1 + 0.0256 / 1.2321 ) = ln( 1.020778 ) = 0.020565 sigma = sqrt(0.020565) = 0.14341 mu_log = ln(1+0.11) − 0.5 x 0.020565 = 0.104360 − 0.010283 = 0.094077

ಈ ಪರಿವರ್ತನೆ ಮುಖ್ಯ: ಇದು ಖಚಿತಪಡಿಸುತ್ತದೆ ಸಿಮ್ಯುಲೇಟ್ ಆದ returns ನ average ನಿಜವಾಗಿಯೂ 11% ಆಗಿರುತ್ತದೆ ಎಂದು. ಇಲ್ಲದಿದ್ದರೆ model ವ್ಯವಸ್ಥಿತವಾಗಿ ಕಡಿಮೆ return ಕೊಡುತ್ತಿತ್ತು.

5.2 ಹಂತ 2 — ಪ್ರತಿ ತಿಂಗಳ ಚಕ್ರ

ಪ್ರತಿ path ನಲ್ಲಿ, ಪ್ರತಿ ತಿಂಗಳು ಈ ಕ್ರಮದಲ್ಲಿ ನಡೆಯುತ್ತದೆ:

// v = portfolio value, w = ಈ ತಿಂಗಳ withdrawal 1. v = v − w // ಮೊದಲು ಹಣ ತೆಗೆ 2. g = exp( mu_log + sigma x gauss() ) − 1 // ಈ ತಿಂಗಳ random return 3. v = v x max(0, g + 1 − fee) // growth, fee ಕಳೆದು 4. ವರ್ಷ ಮುಗಿದರೆ ಮತ್ತು inflationAdjust ON: w = w x (1 + inflation) // ಮುಂದಿನ ವರ್ಷ ಹೆಚ್ಚು ತೆಗೆ 5. v <= 0 ಆದರೆ → ಈ path FAIL, ಇಲ್ಲಿಗೆ ನಿಲ್ಲು
ಗಮನಿಸಿ — ಕ್ರಮ ಮುಖ್ಯ

ಹಣ ಮೊದಲು ತೆಗೆದು ಆಮೇಲೆ growth. ಇದು ತಿಂಗಳ ಆರಂಭದಲ್ಲಿ ಖರ್ಚಿಗೆ ಹಣ ಬೇಕು ಎಂಬ ವಾಸ್ತವಕ್ಕೆ ಸರಿ, ಮತ್ತು ಇದು ಸ್ವಲ್ಪ conservative — ಅಂದರೆ ಸುರಕ್ಷಿತ ಕಡೆಗೆ ವಾಲುತ್ತದೆ.

5.4 Randomness — mulberry32 ಮತ್ತು Box-Muller

Calculator JavaScript ನ Math.random() ಬಳಸುವುದಿಲ್ಲ, ಯಾಕೆಂದರೆ ಅದನ್ನು seed ಮಾಡಲಾಗದು. ಬದಲಿಗೆ mulberry32 ಎಂಬ seeded PRNG ಬಳಸುತ್ತದೆ. ಪ್ರತಿ path ಗೆ ಬೇರೆ seed:

path i ನ seed = baseSeed + i x 7919 + 1 // 7919 ಒಂದು prime — paths ನಡುವೆ correlation ತಪ್ಪಿಸಲು

ಆ uniform random numbers ಅನ್ನು Box-Muller transform ಬಳಸಿ normal (Gaussian) ಗೆ ಪರಿವರ್ತಿಸಲಾಗುತ್ತದೆ. ಫಲಿತಾಂಶ: ಒಂದೇ seed ಕೊಟ್ಟರೆ ನೀವು ಎಷ್ಟು ಬಾರಿ run ಮಾಡಿದರೂ ನಿಖರವಾಗಿ ಒಂದೇ ಉತ್ತರ ಬರುತ್ತದೆ.

// ಆರಂಭದ ಗಡಿಗಳು lo = 0 // ಏನೂ ತೆಗೆಯದಿದ್ದರೆ 100% success hi = max(1000, corpus / 12) // ಖಂಡಿತಾ ವಿಫಲ ಆಗುವ ದೊಡ್ಡ ಮೊತ್ತ // feasibility check evaluate(1) ನ success < target → feasible = false // ₹1 ತೆಗೆದರೂ target ಸಿಗದಿದ್ದರೆ corpus ಸಾಲದು // ಮುಖ್ಯ loop while (hi − lo > 50 AND iter < 40): mid = (lo + hi) / 2 ಒಂದು ವೇಳೆ evaluate(mid).rate >= target: lo = mid // ಇನ್ನೂ ಜಾಸ್ತಿ ತೆಗೆಯಬಹುದು ಇಲ್ಲದಿದ್ದರೆ: hi = mid // ತುಂಬಾ ಜಾಸ್ತಿ ಆಯಿತು ಉತ್ತರ = lo

6.1 "Not feasible" ಬಂದರೆ ಏನು ಮಾಡಬೇಕು

ನಿಮ್ಮ corpus ತುಂಬಾ ಚಿಕ್ಕದು ಅಥವಾ target success ತುಂಬಾ ಹೆಚ್ಚು ಆದರೆ solver "not feasible" ಎನ್ನುತ್ತದೆ. ಆಗ ಈ ಐದರಲ್ಲಿ ಒಂದನ್ನು ಬದಲಾಯಿಸಬೇಕು:

  2. Horizon ಕಡಿಮೆ ಮಾಡಿ — ಆದರೆ ಇದು ಸುಳ್ಳು ಸಮಾಧಾನ. ನೀವು ಬದುಕುವುದನ್ನು ನಿಲ್ಲಿಸಲಾಗದು.

  5. Corpus ಹೆಚ್ಚಿಸಿ / retirement ಮುಂದೂಡಿ — ಕಷ್ಟ ಆದರೆ ಅತ್ಯಂತ ಪ್ರಾಮಾಣಿಕ ದಾರಿ.

10. ಸಾಮಾನ್ಯ ತಪ್ಪುಗಳು — Common Mistakes

ತಪ್ಪು 1 — Inflation-adjust OFF ಇಟ್ಟು ದೊಡ್ಡ ಸಂಖ್ಯೆ ನೋಡಿ ಖುಷಿ ಪಡುವುದು

OFF ಇಟ್ಟರೆ 30 ವರ್ಷ ಅದೇ nominal ಮೊತ್ತ ಸಿಗುತ್ತದೆ. 6% inflation ನಲ್ಲಿ 30 ವರ್ಷದ ನಂತರ ₹61,400 ನ ಕೊಳ್ಳುವ ಶಕ್ತಿ ಇಂದಿನ ₹10,700 ಗೆ ಸಮ. ಅಂದರೆ ನೀವು 88 ವರ್ಷಕ್ಕೆ ಬಡವರಾಗಿ ಬದುಕುತ್ತೀರಿ. ಯಾವಾಗಲೂ ON ಇಡಿ.

ತಪ್ಪು 2 — Expected return ಗೆ ಹಿಂದಿನ 5 ವರ್ಷದ fund return ಹಾಕುವುದು

ಕಳೆದ 5 ವರ್ಷದಲ್ಲಿ ನಿಮ್ಮ fund 18% ಕೊಟ್ಟಿರಬಹುದು. ಆದರೆ ಅದು ಒಂದು bull market. ದೀರ್ಘಕಾಲದ ವಾಸ್ತವಿಕ ಸಂಖ್ಯೆ ಬಳಸಿ — Indian equity ಗೆ 11–12%, ಮತ್ತು ನಿಮ್ಮ portfolio ನಲ್ಲಿ debt ಇದ್ದರೆ ಇನ್ನೂ ಕಡಿಮೆ.

ತಪ್ಪು 3 — SD ಅನ್ನು ಕಡಿಮೆ ಇಡುವುದು ಅಥವಾ 0 ಮಾಡುವುದು

SD ಕಡಿಮೆ ಮಾಡಿದರೆ ಉತ್ತರ ಸುಂದರವಾಗಿ ಕಾಣುತ್ತದೆ. ಆದರೆ ನೀವು ಈ calculator ನ ಇಡೀ ಉದ್ದೇಶವನ್ನೇ ಕೊಂದಂತೆ. Volatility ಇಲ್ಲದೆ sequence risk ಇಲ್ಲ, sequence risk ಇಲ್ಲದೆ ಇದು ಬರೀ Excel.

ತಪ್ಪು 4 — ಮನೆಯ ಬೆಲೆಯನ್ನು corpus ನಲ್ಲಿ ಸೇರಿಸುವುದು

ನೀವು ವಾಸಿಸುವ ಮನೆ ಒಂದು asset ಆದರೂ, ಅದನ್ನು ಪ್ರತಿ ತಿಂಗಳು ಸ್ವಲ್ಪ ಸ್ವಲ್ಪ ಮಾರಿ ದಿನಸಿ ಕೊಳ್ಳಲಾಗದು. ಬಾಡಿಗೆಗೆ ಕೊಟ್ಟ ಮನೆಯ ಬಾಡಿಗೆ ಆದಾಯವನ್ನು ಮಾತ್ರ ನಿಮ್ಮ ಅಗತ್ಯದಿಂದ ಕಳೆಯಿರಿ.

ತಪ್ಪು 5 — Tax ಅನ್ನು ಮರೆಯುವುದು

ಈ calculator ನ withdrawal pre-tax. ನೀವು equity MF ಮಾರಿದಾಗ LTCG (12.5%, ₹1.25L ವಿನಾಯಿತಿಯ ಮೇಲೆ) ಕಟ್ಟಬೇಕು. ಆದ್ದರಿಂದ ನಿಮಗೆ ₹61,400 ಕೈಗೆ ಬೇಕಾದರೆ ಸ್ವಲ್ಪ ಹೆಚ್ಚು ಮಾರಬೇಕು. ಇದಕ್ಕೆ LTCG Harvest Optimiser ಬಳಸಿ.

ತಪ್ಪು 6 — ಒಂದೇ ಬಾರಿ ಲೆಕ್ಕ ಹಾಕಿ ಮರೆತು ಬಿಡುವುದು

30 ವರ್ಷದ ಒಂದೇ ನಿರ್ಧಾರವನ್ನು ಇಂದೇ ಮಾಡುವುದು ಅಸಾಧ್ಯ. ಇದು ಒಂದು ಆರಂಭ ಬಿಂದು, ಅಂತಿಮ ಉತ್ತರ ಅಲ್ಲ.

ತಪ್ಪು 7 — 99% target ಗೆ ಹಠ ಹಿಡಿಯುವುದು

99% success ಗೆ ನೀವು ಎಷ್ಟು ಕಡಿಮೆ ಖರ್ಚು ಮಾಡಬೇಕಾಗುತ್ತದೆ ಎಂದರೆ, ಬಹುತೇಕ ಸನ್ನಿವೇಶಗಳಲ್ಲಿ ನೀವು ಬಳಸದೇ ಬಿಟ್ಟ ಕೋಟಿಗಟ್ಟಲೆ ಹಣ ಉಳಿಯುತ್ತದೆ. "ಹಣ ಮುಗಿಯುವ ಅಪಾಯ" ಮತ್ತು "ಬದುಕದೆ ಸಾಯುವ ಅಪಾಯ" — ಎರಡೂ ನಿಜವಾದ ಅಪಾಯಗಳು.

ತಪ್ಪು 8 — Paths ಕಡಿಮೆ ಇಟ್ಟು ಫಲಿತಾಂಶ ನಂಬುವುದು

200 paths ನಲ್ಲಿ ಉತ್ತರ ಪ್ರತಿ seed ಗೆ ಬದಲಾಗುತ್ತದೆ. ಕನಿಷ್ಠ 1,000 ಬಳಸಿ. ಪರೀಕ್ಷೆ: seed 3 ಬಾರಿ ಬದಲಾಯಿಸಿ. ಉತ್ತರ ₹2,000 ಗಿಂತ ಹೆಚ್ಚು ಬದಲಾದರೆ paths ಹೆಚ್ಚಿಸಿ.
