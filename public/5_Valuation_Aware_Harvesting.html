1. ಈ calculator ಏನು ಮಾಡುತ್ತದೆ

ನಿವೃತ್ತಿಯಲ್ಲಿ ನೀವು ಪ್ರತಿ ತಿಂಗಳು ಹಣ ತೆಗೆಯಬೇಕು. ಆ ಹಣ ಎಲ್ಲಿಂದ ಬರುತ್ತದೆ? ಎರಡು ಆಯ್ಕೆಗಳಿವೆ — equity ಮಾರಿ ಅಥವಾ debt ಮಾರಿ. ಸಾಮಾನ್ಯ ವಿಧಾನ: ಪ್ರತಿ ವರ್ಷ ಸ್ಥಿರ ಪ್ರಮಾಣದಲ್ಲಿ equity ಮಾರಿ debt bucket ತುಂಬಿಸು.

ಆದರೆ ಒಂದು ಸ್ಪಷ್ಟ ಪ್ರಶ್ನೆ ಉಳಿಯುತ್ತದೆ — ಮಾರುಕಟ್ಟೆ P/E 32 ಇರುವಾಗಲೂ, P/E 13 ಇರುವಾಗಲೂ ಒಂದೇ ಪ್ರಮಾಣದಲ್ಲಿ ಮಾರುವುದು ಸರಿಯೇ? ದುಬಾರಿಯಾಗಿದ್ದಾಗ ಹೆಚ್ಚು ಮಾರಿ, ಅಗ್ಗವಾಗಿದ್ದಾಗ ಕಡಿಮೆ ಮಾರುವುದು ತರ್ಕಬದ್ಧವಾಗಿ ಕಾಣುತ್ತದೆ.

2. ಯಾವ ಸಮಸ್ಯೆ ಬಗೆಹರಿಸುತ್ತದೆ

ಸಮಸ್ಯೆ 1 — "Market timing ಕೆಟ್ಟದು" ಎಂಬ ನಿಯಮಕ್ಕೆ ಒಂದು ಅಪವಾದವಿದೆಯೇ?

ಪ್ರತಿ ಹೂಡಿಕೆ ಪುಸ್ತಕ ಹೇಳುತ್ತದೆ — market timing ಮಾಡಬೇಡಿ. ಅದು ಸರಿ, ಆದರೆ ಆ ಸಲಹೆ ಸಂಗ್ರಹ ಹಂತಕ್ಕೆ. ನೀವು ಹಣ ಸೇರಿಸುತ್ತಿರುವಾಗ, ಯಾವಾಗ ಖರೀದಿಸಬೇಕು ಎಂದು ಊಹಿಸುವುದು ವ್ಯರ್ಥ.

ಆದರೆ ನಿವೃತ್ತಿಯಲ್ಲಿ ಪರಿಸ್ಥಿತಿ ಬೇರೆ. ನೀವು ಮಾರಲೇಬೇಕು — ಆಯ್ಕೆಯಿಲ್ಲ. ಪ್ರಶ್ನೆ "ಮಾರಬೇಕೇ?" ಅಲ್ಲ, "ಎಲ್ಲಿಂದ ಮತ್ತು ಎಷ್ಟು ಮಾರಬೇಕು?" ಇದು timing ಅಲ್ಲ, sequencing. ಈ ವ್ಯತ್ಯಾಸ ಸೂಕ್ಷ್ಮ ಆದರೆ ನಿರ್ಣಾಯಕ.

ಒಂದು ಸಾದೃಶ್ಯ

ನಿಮ್ಮ ಮನೆಯಲ್ಲಿ ಎರಡು ನೀರಿನ ಟ್ಯಾಂಕ್ ಇವೆ — ಒಂದು ಮಳೆನೀರು (ಅನಿಶ್ಚಿತ, equity), ಇನ್ನೊಂದು ಸಂಗ್ರಹಿತ (ಖಚಿತ, debt). ನೀವು ಪ್ರತಿ ದಿನ ಸಂಗ್ರಹಿತ ಟ್ಯಾಂಕ್‌ನಿಂದ ಕುಡಿಯುತ್ತೀರಿ. ಆಗಾಗ ಮಳೆನೀರನ್ನು ಸಂಗ್ರಹಿತ ಟ್ಯಾಂಕ್‌ಗೆ ವರ್ಗಾಯಿಸಬೇಕು. ಪ್ರಶ್ನೆ — ಮಳೆ ಜೋರಾಗಿ ಸುರಿಯುತ್ತಿರುವಾಗ ಹೆಚ್ಚು ವರ್ಗಾಯಿಸಬೇಕೇ? ಅದೇ valuation-aware harvesting.

ಸಮಸ್ಯೆ 2 — ದೊಡ್ಡ ಕುಸಿತದ ಮೊದಲು ಲಾಭ ಕಾಪಾಡಿಕೊಳ್ಳುವುದು

2007 ರ ಕೊನೆಯಲ್ಲಿ Sensex P/E 28 ದಾಟಿತ್ತು. 2008 ರಲ್ಲಿ ಮಾರುಕಟ್ಟೆ 52% ಬಿತ್ತು. 2020 ಮಾರ್ಚ್‌ನಲ್ಲಿ P/E 17 ಕ್ಕೆ ಇಳಿಯಿತು — ಮುಂದಿನ 18 ತಿಂಗಳಲ್ಲಿ ಮಾರುಕಟ್ಟೆ ದ್ವಿಗುಣಗೊಂಡಿತು.

ಹಿಂದಿನಿಂದ ನೋಡಿದರೆ ಇದು ಸ್ಪಷ್ಟ. ಆದರೆ ಆ ಕ್ಷಣದಲ್ಲಿ ನಿಂತು ನೋಡಿದರೆ? 2007 ರಲ್ಲಿ ಎಲ್ಲರೂ "ಇದು ಹೊಸ ಯುಗ" ಎಂದಿದ್ದರು. 2020 ರ ಮಾರ್ಚ್‌ನಲ್ಲಿ ಎಲ್ಲರೂ "ಇದು ಮುಗಿಯಿತು" ಎಂದಿದ್ದರು. Valuation signal ಆ ಭಾವನೆಗಳನ್ನು ಕಡೆಗಣಿಸಿ ಒಂದು ಯಾಂತ್ರಿಕ ನಿಯಮ ಕೊಡುತ್ತದೆ.

ಸಮಸ್ಯೆ 3 — ಆದರೆ ಇದು ನಿಜವಾಗಿ ಲಾಭ ಕೊಡುತ್ತದೆಯೇ?

ಇಲ್ಲಿಯೇ ಹೆಚ್ಚಿನ ಲೇಖನಗಳು ನಿಲ್ಲುತ್ತವೆ. ಅವು ತಂತ್ರವನ್ನು ವಿವರಿಸುತ್ತವೆ, ಒಂದೆರಡು ಐತಿಹಾಸಿಕ ಉದಾಹರಣೆ ಕೊಡುತ್ತವೆ, ಮತ್ತು "ಆದ್ದರಿಂದ ಇದು ಒಳ್ಳೆಯದು" ಎಂದು ಮುಗಿಸುತ್ತವೆ.

ಅದು ಸಾಕಾಗದು. ಎರಡು ಉದಾಹರಣೆ ಆಯ್ಕೆ ಪಕ್ಷಪಾತ (selection bias). ನಿಜವಾದ ಪರೀಕ್ಷೆಗೆ ನೂರಾರು ವಿಭಿನ್ನ ಮಾರುಕಟ್ಟೆ ಪಥಗಳು ಬೇಕು — ಕೆಲವು mean-reverting, ಕೆಲವು ಅಲ್ಲ. ಈ calculator ಅದನ್ನೇ ಮಾಡುತ್ತದೆ: 800 ಸ್ವತಂತ್ರ P/E ಪಥಗಳು, ಪ್ರತಿಯೊಂದರ ಮೇಲೂ ಎರಡೂ ತಂತ್ರಗಳು.

ಈ calculator ನ ಅತ್ಯಂತ ಪ್ರಾಮಾಣಿಕ ಭಾಗ

ಇದರಲ್ಲಿ ಒಂದು control experiment ಇದೆ. reversion ಅನ್ನು 0 ಗೆ ಇಟ್ಟರೆ P/E ಒಂದು random walk ಆಗುತ್ತದೆ — ಅಂದರೆ ದುಬಾರಿ ಮಾರುಕಟ್ಟೆ ಅಗ್ಗವಾಗುವ ಯಾವುದೇ ಪ್ರವೃತ್ತಿ ಇಲ್ಲ. ಆಗ aware ತಂತ್ರದ ಎಲ್ಲ ಅನುಕೂಲ ಕಣ್ಮರೆಯಾಗಬೇಕು. ಅದು ಆಗದಿದ್ದರೆ ನಿಮ್ಮ ಫಲಿತಾಂಶ ಒಂದು bug. §6 ನಲ್ಲಿ ಇದನ್ನು ವಿವರವಾಗಿ ನೋಡೋಣ.

Refill target ಸೂತ್ರ

refillTarget = w × (1 + inflation) × ieDuration × mult // w = ಈಗಿನ ವಾರ್ಷಿಕ ಖರ್ಚು // ieDuration = income bucket ಎಷ್ಟು ವರ್ಷ ಇರಬೇಕು (default 5) // mult = valuation multiplier — ಇಲ್ಲಿಯೇ ತಂತ್ರ ಬದಲಾಗುತ್ತದೆ

Fixed ತಂತ್ರದಲ್ಲಿ mult ಯಾವಾಗಲೂ 1.0. Aware ತಂತ್ರದಲ್ಲಿ ಅದು P/E ಯನ್ನು ಅವಲಂಬಿಸಿ ಬದಲಾಗುತ್ತದೆ.

Valuation multiplier

ratio = pe[ವರ್ಷ] / peMean if (ratio >= richBand) mult = richMult // 1.15 ದಾಟಿದರೆ 1.6 else if (ratio <= cheapBand) mult = cheapMult // 0.85 ಕ್ಕಿಂತ ಕೆಳಗಾದರೆ 0.6 else mult = 1.0 // ನಡುವೆ ಇದ್ದರೆ ಸಾಮಾನ್ಯ

5. ಒಳಗಿನ Math — OU mean reversion

P/E ಪಥ ಹೇಗೆ ಸೃಷ್ಟಿಯಾಗುತ್ತದೆ

ಈ calculator ನ ಅತ್ಯಂತ ಮುಖ್ಯ ಸಾಲುಗಳು ಇವು:

lnPE = lnPE + kappa × (lnMean − lnPE) + sigma × gauss(); lnPE = clamp(lnPE, ln(6), ln(70)); pe = exp(lnPE);

ಇದನ್ನು Ornstein-Uhlenbeck (OU) process ಎನ್ನುತ್ತಾರೆ. ಮೂರು ಭಾಗ ಒಡೆದು ನೋಡೋಣ.

ಭಾಗ 1 — ಏಕೆ log?

P/E ನೇರವಾಗಿ ಬಳಸುವ ಬದಲು ಅದರ logarithm ಬಳಸಲಾಗುತ್ತದೆ. ಎರಡು ಕಾರಣ. ಮೊದಲನೆಯದು — P/E ಎಂದೂ ಋಣಾತ್ಮಕವಾಗಲಾರದು, ಮತ್ತು exp() ಯಾವಾಗಲೂ ಧನಾತ್ಮಕ ಕೊಡುತ್ತದೆ. ಎರಡನೆಯದು — 20 ರಿಂದ 24 ಗೆ ಚಲನೆ (20% ಏರಿಕೆ) ಮತ್ತು 30 ರಿಂದ 36 ಗೆ ಚಲನೆ (ಅದೇ 20%) ಒಂದೇ ಗಾತ್ರದವು ಎಂದು log scale ಸರಿಯಾಗಿ ಪರಿಗಣಿಸುತ್ತದೆ.

ಭಾಗ 2 — pull term: kappa × (lnMean − lnPE)

kappa = reversion / 100 = 0.15 lnMean = ln(20) = 2.9957 // ಈಗ P/E = 26 ಎಂದುಕೊಳ್ಳಿ lnPE = ln(26) = 3.2581 ಅಂತರ = 2.9957 − 3.2581 = −0.2624 pull = 0.15 × (−0.2624) = −0.03936 // ಯಾದೃಚ್ಛಿಕ ಆಘಾತವಿಲ್ಲದೆ ಹೊಸ lnPE = 3.2581 − 0.03936 = 3.2187 ಹೊಸ P/E = exp(3.2187) = 24.99

ಒಂದು ವರ್ಷದಲ್ಲಿ P/E 26 ರಿಂದ 25 ಕ್ಕೆ. ನಿಧಾನ ಎಳೆತ. ಗಮನಿಸಿ pull ನ ಚಿಹ್ನೆ ಸ್ವಯಂಚಾಲಿತ — P/E ಸರಾಸರಿಗಿಂತ ಮೇಲಿದ್ದರೆ ಋಣಾತ್ಮಕ (ಕೆಳಗೆ ಎಳೆಯುತ್ತದೆ), ಕೆಳಗಿದ್ದರೆ ಧನಾತ್ಮಕ (ಮೇಲೆ ಎಳೆಯುತ್ತದೆ).

ಭಾಗ 3 — shock term: sigma × gauss()

sigma = peVol / 100 = 0.18 gauss() = ಪ್ರಮಾಣಿತ ಸಾಮಾನ್ಯ ಯಾದೃಚ್ಛಿಕ ಸಂಖ್ಯೆ (ಸರಾಸರಿ 0, SD 1) // ಒಂದು ಕೆಟ್ಟ ವರ್ಷ: gauss() = −1.5 shock = 0.18 × (−1.5) = −0.27 ಹೊಸ lnPE = 3.2581 − 0.03936 − 0.27 = 2.9487 ಹೊಸ P/E = exp(2.9487) = 19.08

ಈ ಒಂದೇ ವರ್ಷದಲ್ಲಿ P/E 26 ರಿಂದ 19 ಕ್ಕೆ — 27% ಕುಸಿತ ಬರೀ multiple ನಲ್ಲಿ. ಗಮನಿಸಿ shock (0.27) pull (0.039) ಗಿಂತ ಏಳು ಪಟ್ಟು ದೊಡ್ಡದು. ಇದೇ ಈ ಮಾದರಿಯ ಪ್ರಮುಖ ಸತ್ಯ.

ಇದನ್ನು ಚೆನ್ನಾಗಿ ಅರ್ಥ ಮಾಡಿಕೊಳ್ಳಿ

ಒಂದೇ ವರ್ಷದಲ್ಲಿ ಯಾದೃಚ್ಛಿಕ ಆಘಾತ mean reversion ಗಿಂತ ಬಹಳ ದೊಡ್ಡದು. ಆದ್ದರಿಂದ "ಮಾರುಕಟ್ಟೆ ದುಬಾರಿಯಾಗಿದೆ" ಎಂದು ತಿಳಿದರೂ ಮುಂದಿನ ವರ್ಷ ಏನಾಗುತ್ತದೆ ಎಂದು ಊಹಿಸಲಾಗದು. Mean reversion ಒಂದು ದೀರ್ಘಾವಧಿ ಒಲವು, ಅಲ್ಪಾವಧಿ ಭವಿಷ್ಯವಾಣಿ ಅಲ್ಲ. ಇದೇ ಕಾರಣಕ್ಕೆ aware ತಂತ್ರದ ಅನುಕೂಲ ಸಣ್ಣದಾಗಿರುತ್ತದೆ ಮತ್ತು ಎಲ್ಲ paths ನಲ್ಲಿ ಕೆಲಸ ಮಾಡುವುದಿಲ್ಲ.

ಭಾಗ 4 — clamp: ವಾಸ್ತವಿಕ ಮಿತಿಗಳು

lnPE = clamp(lnPE, ln(6), ln(70)) // P/E ಎಂದೂ 6 ಕ್ಕಿಂತ ಕೆಳಗೆ ಅಥವಾ 70 ಕ್ಕಿಂತ ಮೇಲೆ ಹೋಗುವುದಿಲ್ಲ

ಇಲ್ಲದಿದ್ದರೆ ಸತತ ಕೆಟ್ಟ ಆಘಾತಗಳು P/E ಅನ್ನು 2 ಅಥವಾ 200 ಕ್ಕೆ ಒಯ್ಯಬಹುದು — ಅವು ಎಂದೂ ಸಂಭವಿಸಿಲ್ಲ. ಈ ಮಿತಿಗಳು ಐತಿಹಾಸಿಕ ಅನುಭವಕ್ಕೆ ಸರಿಸುಮಾರು ಹೊಂದುತ್ತವೆ.

Return ಹೇಗೆ ಲೆಕ್ಕವಾಗುತ್ತದೆ — ಇದೇ ಚಾಣಾಕ್ಷ ಭಾಗ

ಇಲ್ಲಿ ಈ calculator ಒಂದು ಮುಖ್ಯ ವಿನ್ಯಾಸ ನಿರ್ಧಾರ ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. Equity return ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಸೃಷ್ಟಿಸುವುದಿಲ್ಲ — ಅದನ್ನು P/E ಪಥದಿಂದಲೇ ಪಡೆಯುತ್ತದೆ.

ret = (1 + g) × (pe[y] / pe[y−1]) − 1 + dy // g = earningsGrowth / 100 = 0.10 // dy = dividendYield / 100 = 0.014

ಈ ಸೂತ್ರ ಎಲ್ಲಿಂದ ಬಂತು

ಬೆಲೆ = ಗಳಿಕೆ × P/E ಬೆಲೆ[y] / ಬೆಲೆ[y−1] = (ಗಳಿಕೆ[y] / ಗಳಿಕೆ[y−1]) × (pe[y] / pe[y−1]) = (1 + g) × (pe[y] / pe[y−1]) // ಒಟ್ಟು return = ಬೆಲೆ ಬದಲಾವಣೆ + ಡಿವಿಡೆಂಡ್
ಇದು ಏಕೆ ಬೌದ್ಧಿಕವಾಗಿ ಪ್ರಾಮಾಣಿಕ

ಒಂದು ಸೋಮಾರಿ ವಿನ್ಯಾಸ ಹೀಗಿರುತ್ತಿತ್ತು — "P/E ದುಬಾರಿಯಾಗಿದ್ದರೆ ಮುಂದಿನ ವರ್ಷದ return ಕಡಿಮೆ ಇರಲಿ." ಅದು ತೀರ್ಮಾನವನ್ನೇ ಊಹಿಸುವುದು (assuming the conclusion). ಆಗ aware ತಂತ್ರ ಗೆಲ್ಲುವುದು ಖಚಿತ, ಆದರೆ ಅದು ನಿಮ್ಮದೇ ಊಹೆಯನ್ನು ಮತ್ತೆ ಹೇಳಿದಂತೆ.

ಇಲ್ಲಿ ಬದಲಿಗೆ, return ಗಳಿಕೆ ಬೆಳವಣಿಗೆ ಮತ್ತು multiple ನ ಬದಲಾವಣೆಯಿಂದ ಸ್ವಾಭಾವಿಕವಾಗಿ ಹೊರಹೊಮ್ಮುತ್ತದೆ. Mean reversion ಇದ್ದರೆ ದುಬಾರಿ ಮಾರುಕಟ್ಟೆಯ ನಂತರ ಕಡಿಮೆ return ತಾನಾಗಿ ಬರುತ್ತದೆ. ಇಲ್ಲದಿದ್ದರೆ ಬರುವುದಿಲ್ಲ. ಇದೇ ಸರಿಯಾದ ರಚನೆ.

ಒಂದು ಪೂರ್ಣ ವರ್ಷದ ಲೆಕ್ಕ

ವರ್ಷ 4 → ವರ್ಷ 5, P/E 26 ರಿಂದ 19.08

pe[4] = 26.00, pe[5] = 19.08 g = 0.10, dy = 0.014 ret = (1.10) × (19.08 / 26.00) − 1 + 0.014 = 1.10 × 0.73385 − 1 + 0.014 = 0.80723 − 1 + 0.014 = −17.9%

ಗಳಿಕೆ 10% ಬೆಳೆದರೂ multiple 27% ಕುಸಿದಿದ್ದರಿಂದ ಒಟ್ಟು return −17.9%. ಇದೇ 2008 ಮತ್ತು 2000 ರಲ್ಲಿ ನಿಜವಾಗಿ ನಡೆದದ್ದು — ಕಂಪನಿಗಳ ಗಳಿಕೆ ಕುಸಿಯಲಿಲ್ಲ, ಜನರು ಆ ಗಳಿಕೆಗೆ ಕೊಡುವ ಬೆಲೆ ಕುಸಿಯಿತು.

ವಿರುದ್ಧ ದಿಕ್ಕು — P/E 15 ರಿಂದ 19 ಗೆ ಚೇತರಿಕೆ

ret = (1.10) × (19 / 15) − 1 + 0.014 = 1.10 × 1.26667 − 1 + 0.014 = 1.39333 − 1 + 0.014 = +40.7%

ಇದೇ 2009 ಮತ್ತು 2021 ರಲ್ಲಿ ನಡೆದದ್ದು. ಗಮನಿಸಿ — ಈ ಅದ್ಭುತ ವರ್ಷವನ್ನು ಪಡೆಯಲು ನೀವು ಆಗ equity ಹೊಂದಿರಬೇಕು. ಅಗ್ಗವಾಗಿದ್ದಾಗ ಕಡಿಮೆ ಮಾರುವ (cheapMult 0.6) ನಿಯಮದ ಸಂಪೂರ್ಣ ಉದ್ದೇಶ ಇದೇ.

ಒಂದು ವರ್ಷದ ಪೂರ್ಣ ಚಕ್ರ (ಎರಡೂ ತಂತ್ರಗಳಿಗೆ ಒಂದೇ)

ತಪ್ಪು 5 — P/E ಸರಾಸರಿ ಸ್ಥಿರ ಎಂದು ಭಾವಿಸುವುದು

peMean = 20 ಎಂದು ಇಟ್ಟಿದ್ದೇವೆ. ಆದರೆ ಸರಾಸರಿ P/E ಸ್ವತಃ ಬದಲಾಗಬಹುದು. ಬಡ್ಡಿದರ ಕಡಿಮೆಯಾದರೆ, ಆರ್ಥಿಕತೆ ಹೆಚ್ಚು ಸೇವಾ-ಆಧಾರಿತವಾದರೆ, ಅಥವಾ ಹೆಚ್ಚು ವಿದೇಶಿ ಬಂಡವಾಳ ಬಂದರೆ ನ್ಯಾಯಸಮ್ಮತ P/E 24 ಆಗಬಹುದು. ಆಗ ನಿಮ್ಮ ತಂತ್ರ ಯಾವಾಗಲೂ "ದುಬಾರಿ" ಎಂದು ಭಾವಿಸಿ ಬಹಳ ಬೇಗ ಮಾರುತ್ತಲೇ ಇರುತ್ತದೆ.

ತಪ್ಪು 6 — ಒಂದೇ ವರ್ಷದ ಫಲಿತಾಂಶದಿಂದ ತಂತ್ರ ಬಿಡುವುದು

ವರ್ಷ 1 ರಲ್ಲಿ aware ತಂತ್ರ ₹2.3 ಲಕ್ಷ ಹಿಂದಿತ್ತು (ಮೇಲಿನ ಉದಾಹರಣೆ ನೋಡಿ). ಬಹಳ ಜನ ಅಲ್ಲೇ ಬಿಟ್ಟುಬಿಡುತ್ತಾರೆ. ಆದರೆ ಈ ತಂತ್ರದ ಸಂಪೂರ್ಣ ಮೌಲ್ಯ ದೊಡ್ಡ ಕುಸಿತದ ಸಮಯದಲ್ಲಿ ಬರುತ್ತದೆ. ಅಂತಹ ಕುಸಿತ 30 ವರ್ಷಗಳಲ್ಲಿ ಬಹುಶಃ 3–4 ಬಾರಿ ಬರುತ್ತದೆ. ಅಲ್ಲಿಯವರೆಗೆ ಇದು ಬರೀ ವೆಚ್ಚದಂತೆ ಕಾಣುತ್ತದೆ.

ತಪ್ಪು 7 — ಇದನ್ನು ಪ್ರತ್ಯೇಕ stocks ಗೆ ಅನ್ವಯಿಸುವುದು

ಈ ಇಡೀ ತರ್ಕ ಸೂಚ್ಯಂಕದ (index) P/E ಗೆ. ಒಂದು ಪ್ರತ್ಯೇಕ ಕಂಪನಿಯ P/E 40 ಇರುವುದು ಅದು ದುಬಾರಿ ಎಂದಲ್ಲ — ಅದು ವೇಗವಾಗಿ ಬೆಳೆಯುತ್ತಿರಬಹುದು. ಅಥವಾ P/E 8 ಇರುವುದು ಅಗ್ಗ ಎಂದಲ್ಲ — ಅದು ಸಾಯುತ್ತಿರಬಹುದು. ಸೂಚ್ಯಂಕದ mean reversion ವೈವಿಧ್ಯೀಕರಣದಿಂದ ಬರುತ್ತದೆ, ಪ್ರತ್ಯೇಕ ಕಂಪನಿಗಳಲ್ಲಿ ಆ ಗುಣ ಇಲ್ಲ.

ತಪ್ಪು 8 — ieDuration ಅನ್ನು ತೀರಾ ಚಿಕ್ಕದಾಗಿ ಇಡುವುದು

ieDuration = 2 ಇಟ್ಟರೆ ಹೆಚ್ಚು equity ಇರುತ್ತದೆ, ದೀರ್ಘಾವಧಿಯಲ್ಲಿ ಹೆಚ್ಚು ಬೆಳೆಯುತ್ತದೆ. ಆದರೆ ಒಂದು ಸತತ ಮೂರು ವರ್ಷದ ಕುಸಿತದಲ್ಲಿ ನಿಮ್ಮ income bucket ಖಾಲಿಯಾಗಿ ನೀವು ತಳದಲ್ಲಿ equity ಮಾರಬೇಕಾಗುತ್ತದೆ — ಮತ್ತು ಆಗ valuation ನಿಯಮ ನಿಮಗೆ ಸಹಾಯ ಮಾಡಲಾರದು, ಏಕೆಂದರೆ ಬಲವಂತದ ಮಾರಾಟ ನಿಯಮವನ್ನು ಮೀರುತ್ತದೆ. Bucket ನ ಆಳವೇ ಈ ತಂತ್ರಕ್ಕೆ ಕೆಲಸ ಮಾಡಲು ಅವಕಾಶ ಕೊಡುತ್ತದೆ.

ಸಾರಾಂಶ

Valuation-aware harvesting ಒಂದು ಸಾಧಾರಣ ಆದರೆ ನಿಜವಾದ ಸುಧಾರಣೆ — ಆದರೆ ಅದು ಸಂಪೂರ್ಣವಾಗಿ mean reversion ಎಂಬ ಒಂದೇ ಊಹೆಯ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿದೆ, ಮತ್ತು ಅದರ ಲಾಭ ಸರಾಸರಿಯನ್ನು ಏರಿಸುವುದರಲ್ಲಿ ಅಲ್ಲ, ಕೆಟ್ಟ ಫಲಿತಾಂಶಗಳನ್ನು ಸುಧಾರಿಸುವುದರಲ್ಲಿದೆ.
